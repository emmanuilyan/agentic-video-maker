# Восемь пространственных сцен

Файлы: `assets/techniques/spatial.tsx` — Three.js-геометрия; `spatial-state.ts` — чистые функции траекторий; `index.tsx` регистрирует ID. Используй обычный `PhotoTechnique` с ID из списка:

`SLALOM_FLYTHROUGH`, `ORBIT_GALLERY`, `PHOTO_TUNNEL`, `SPIRAL_FLIGHT`, `DEPTH_DIVE`, `FROZEN_ORBIT`, `EXPLODED_PHOTO`, `PORTAL_ROOMS`.

## Зависимости

Проверенный набор: Remotion / @remotion/three 4.0.522, React 19.2.3, @react-three/fiber 9.7.0, three 0.186.0, @types/three 0.185.4. Устанавливай @remotion/three в версию существующего Remotion через `npx remotion add @remotion/three`; проверь совместимость React и Fiber. Не обновляй чужой проект целиком ради демо.

Для проекта с совпадающими Remotion/React:

```sh
npx remotion add @remotion/three
npm install --save-exact three@0.186.0 @react-three/fiber@9.7.0
npm install --save-dev --save-exact @types/three@0.185.4
```

Весь общий `index.tsx` импортирует 3D-модуль, даже если выбран 2D ID. Если проекту нужны только исходные 2D-приёмы и дополнительные пакеты неуместны, импортируй/адаптируй нужные функции `layouts.tsx` или `effects.tsx` отдельно, без общего 3D-router.

## Время и камера

На вход миров подаётся нормализованный `f=0…179`. Поэтому в `Sequence` при 24 fps и длительности 6 секунд нужно `durationInFrames={144}`, а при 30 fps —180. `cameraFor(kind,f)` возвращает `position`, `target`, `roll`, `fov` и при необходимости `up`. `CameraRig` применяет это состояние до захвата кадра.

Обновляй положение через кадр и React props. Не используй `useFrame`, накопление delta, таймеры или OrbitControls для итогового движения. Повторный рендер кадра78 после кадра140 должен давать то же состояние, что и прямой рендер78.

`ThreeCanvas` получает размеры явно и синхронизирует рендер с Remotion. `useLoader(TextureLoader, sources)` приостанавливает сцену до загрузки всех четырёх текстур. У текстур `SRGBColorSpace`, а фото-материалы не проходят tone mapping. Рамки и пол освещаются отдельно. Для видео-текстур нужен отдельный синхронный механизм; этот пример рассчитан на фотографии.

## Что менять

| Сцена | Настройка |
|---|---|
| Slalom | В `cameraFor`: диапазон Z, амплитуда X, look-ahead и roll. В `Flight`: боковые позиции, шаг Z и ширина карточек. Сохраняй свободный проход между внутренними краями фото. |
| Orbit | Радиус камеры и её высота, полный/неполный угол оборота. Радиус кольца задаётся отдельно в `Orbit`. Слишком близкая камера обрежет ближайшую карточку. |
| Tunnel | Ширина и высота коридора, длина шага секций, закон ускорения. Секции за камерой можно отбрасывать для длинного ролика, но оставляй запас впереди. |
| Spiral | Радиус и высота камеры меняются одновременно с азимутом. Согласуй высоты и азимуты четырёх фото с моментами их прохода. |
| Dive | Вертикальный диапазон, roll и торможение в конце. Для взгляда по −Y используй `up=[0,0,−1]`, иначе up параллелен взгляду. |
| Frozen | `frozenClock` управляет только объектами. Плато42…130 сохраняет состояние мира; `cameraFor` продолжает движение. Не замораживай весь ThreeCanvas. |
| Exploded | Сетка6×4, разброс XYZ/вращений, путь камеры и интервалы действия в пределах каждого 45-кадрового участка. Для каждого тайла создаётся своя UV-геометрия, общая Texture не кропается. |
| Portals | Z стен, ширина и высота проёма, расстояние начала раскрытия. `PhotoRect` образует четыре полосы вокруг отверстия. У последней стены отверстия нет, чтобы финал показывал четвёртое фото. |

## Контроль перед выдачей

- Во всех восьми сценах представлены четыре пользовательских фото; только PHOTO_TUNNEL повторяет их многократно по смыслу раскладки.
- Для обратной стороны карточек используй отдельную плоскость с разворотом на π; double-sided материал сам по себе зеркалит надписи при взгляде сзади.
- В EXPLODED_PHOTO сравни собранный кадр с оригиналом. В коде следующая фотография находится на12 единиц глубже; камера за переход проходит те же12, поэтому масштаб совпадает на границе участков.
- У FROZEN_ORBIT сравни `frozenClock(55)` и `frozenClock(125)` — они равны; cameraFor на этих кадрах различается. Не сравнивай финальные пиксели как в FREEZE_FRAME, потому что камера движется.
- У PORTAL_ROOMS проверь кадры до раскрытия, в проёме и после пересечения стены. Убирай любую непрозрачную заднюю плоскость под проёмом.
- Рендери первый кадр и середину без прогрева: это проверяет ожидание текстур. Для длинных или тяжёлых тоннелей понижай concurrency, а не отключай ожидание загрузки.
