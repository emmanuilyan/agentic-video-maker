# RAPID_PHOTO_FLIPBOOK — быстрый фотофлипбук

## Источник и результат

- Источник: [A$AP Rocky — Sundress](https://www.youtube.com/watch?v=Ec3LoKpGJxY), 1:57.000–1:59.000.
- Результат: composition `PhotoFlipbookReview`, 1280×720, 24 fps, 48 кадров; [одобренный Remotion-рендер](../../assets/previews/RAPID_PHOTO_FLIPBOOK-reference.mp4).
- Реализация: переиспользуемый [PhotoFlipbook](../../assets/techniques/photo-flipbook.tsx) и [демо](src/Demo.tsx).
- Точность: порядок, границы смен и мелкое изменение кадра внутри каждой двухкадровой пары совпадают с исходником. Небольшая разница в детализации возникает при извлечении 1080p кадров в 1280×720 JPEG и повторном кодировании.

## Визуальная схема

По наблюдению, эффект создаётся быстрыми жёсткими склейками полноэкранных фотографических планов. Каждый план длится два кадра при 24 fps, то есть около 83 мс. Внутри некоторых пар есть небольшое движение изображения или фактуры; v2 воспроизводит оба микрокадра. Между планами нет видимого поворота листа, движения карточки, наложения или плавной прозрачности. Крупность и ракурс резко меняются от плана к плану; эта смена масштаба содержимого и даёт ощущение перелистывания. Это описание видимого результата, а не утверждение об устройстве исходного монтажа.

| Слой, сзади вперёд | Содержимое | Нормализованная геометрия | Стиль |
| --- | --- | --- | --- |
| Фон | Тёмный запасной цвет | Весь холст `[0,0,1,1]` | Видим только при незаполненном фото |
| Текущий план | Один элемент из массива, необязательно два микрокадра | Весь холст `[0,0,1,1]` | `object-fit: cover`, обычно `object-position: center` |

В демонстрации использованы кадры из оригинального клипа как конкретные медиа для сопоставления. Компонент принимает произвольные фотографии и не содержит ссылок на клип.

## Таймлайн

Время указано относительно 1:57.000, кадры при 24 fps.

| Время / кадры | Видимое событие | Механика |
| --- | --- | --- |
| 0.000–0.083 с / 0–1 | Крупный план из предыдущего монтажа | Удержание 2 кадра; входит только в демо |
| 0.083 с / 2 | Один блочный переходный кадр | Наблюдается в источнике; в демо воспроизведён отдельным стоп-кадром |
| 0.125 с / 3 | Короткий кадр объятия | Удержание 1 кадр; входит только в демо |
| 0.167–2.000 с / 4–47 | Серия из 22 планов | Каждый план занимает 2 кадра; новый ракурс в кадрах 4, 6, 8, …, 46. В следующем кадре той же пары допустимо микродвижение |

Общая формула для серии: `photoIndex = floor(localFrame / 2)`, где `localFrame = compositionFrame − 4`. Если передан `frameSources`, внутри плана выбирается `frameSources[localFrame % 2]`; иначе одно фото держится оба кадра. Склейка происходит в первый кадр следующего плана.

## Управление эффектом

`PhotoFlipbook` принимает `photos` произвольной длины. У каждого элемента есть `src`, необязательные `holdFrames`, `frameSources` и `objectPosition`. `frameSources` позволяет показать до одного уникального изображения на каждый удерживаемый кадр. Для неподвижных фотографий этот параметр не нужен. `defaultHoldFrames` по умолчанию равен `2`; для другой частоты или ритма его можно изменить. `durationInFrames` задаёт длину вложенной сцены, `frame` позволяет использовать внешний локальный таймер, `fit` выбирает `cover` или `contain`, `background` задаёт цвет свободного поля.

Пример для 24 fps:

```tsx
<PhotoFlipbook
  photos={myPhotos.map((src) => ({src}))}
  durationInFrames={myPhotos.length * 2}
  defaultHoldFrames={2}
  fit="cover"
/>
```

Для 30 fps и похожей длительности снимка выбери 2–3 кадра на фото по требуемому темпу; механическое преобразование 2 кадров при 24 fps равно 2,5 кадрам при 30 fps, поэтому точного целого значения нет.

## Сборка

1. Выбрать разноплановые снимки одной сцены: общие планы, пары, крупные лица и детали. Резкая смена композиции здесь важнее искусственного движения изображения.
2. Подготовить фотографии под холст 16:9 либо задать `objectPosition` для каждого кадра. Не центрировать автоматически снимки с важным объектом у края.
3. Передать массив снимков в `PhotoFlipbook`; задать `defaultHoldFrames={2}` и `durationInFrames={photos.length * 2}` при 24 fps.
4. Разместить компонент в `Sequence` с нужного кадра. В данном сравнении это кадр 4; первые четыре кадра исходника показаны отдельным демо-входом.
5. Если материал содержит движение внутри двухкадровой пары, передать её кадры в `frameSources: [first, second]`. Для чистых фото достаточно `src`.
6. Отрендерить на 24 fps без кроссфейда, blur и easing. Смены должны попадать на чётные локальные кадры.

## Доказательства и неопределённость

- Проверен локальный 1080p H.264-фрагмент источника. `ffprobe`: 1920×1080, 24 fps. Сравнение: 48 кадров от 1:57.000 до 1:59.000.
- Кадры 4–47 в сравнении образуют 22 пары. Первый кадр каждой пары меняет композицию целиком. Разностное изображение соседних кадров одной пары обнаруживает небольшое движение/изменение фактуры, которое было пропущено в v1.
- Однокадровое блочное изображение на кадре 2 есть в обоих доступных кодеках YouTube, но оно относится к входу из предыдущего монтажа. Не включено в переиспользуемый эффект перелистывания.
- Неизвестно, были ли исходные медиа отдельными фотографиями, серийной съёмкой или очень короткими видео. Рецепт фиксирует только видимое поведение.
- Фотографии в демо взяты из источника для измеримого сравнения. Для публикации или другого проекта можно передать собственный набор снимков.
